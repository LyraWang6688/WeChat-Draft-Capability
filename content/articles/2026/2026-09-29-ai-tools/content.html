过去一年多，我换过不少 AI 工具。

ChatGPT、豆包、Coze、Trae、豆包工作、WorkBuddy，再到现在开始直接使用大模型 API 和 Coding Agent。

如果只看工具列表，很容易把这段经历理解成：

我一直在寻找一个更好用的 AI 工具。

但最近回过头来看，我发现真正发生变化的，其实不是工具。

而是我自己。

从最开始把 AI 当成一个聊天对象，到后来希望它真正帮我完成工作；再到关注工具背后的生态、API 和系统集成；直到现在，我开始自己组合模型、代码工具和基础设施来开发产品。

我对 AI 的使用，大概经历了四个阶段。

从四次变化里，我越来越确定一件事：

真正重要的不是找到一个永远“最好用”的 AI 工具，而是知道自己到底要解决什么问题、需要什么能力，以及应该怎样把这些能力组合起来。

01

第一阶段：AI 是我的“智囊团”

2025 年底以前，我最常使用的 AI 其实只有两个：

ChatGPT 和豆包。

两者在我的生活里承担着不同角色。

豆包更像一个生活助手。遇到日常的小问题、需要快速查询的信息，我会习惯性地去问它。

而 ChatGPT 更像我的“智囊团”。

很多时候，我找 ChatGPT 并不是为了获得一个标准答案，而是希望有人陪我把一个问题往下想。

一个想法到底靠不靠谱？一件事情还有没有另外一种理解方式？一个模糊的念头，能不能继续拆成一个真正可以执行的方案？

那时候，我对 AI 的理解其实非常简单：

AI 是一个比搜索引擎更聪明的对话对象。

我关注的是回答质量、知识能力，以及它能不能帮助我思考。

第一阶段的关键词：对话。

02

第二阶段：从“会聊天”到“能交付”

到了 2026 年初，我明显感觉到行业里的讨论开始发生变化。

大家不再只是讨论：

以前更常问

“这个模型回答得聪不聪明？”

后来开始问

“AI 最后到底能不能把事情做出来？”

我的使用习惯也跟着发生了第一次明显变化。

那个阶段，我把自己定位成一个 AI 工具使用者。

虽然当时已经开始自己做一些项目，但整体思路依然是：

什么事情，就去寻找最适合完成这件事情的 AI 工具。

当时我的工具包里，逐渐出现了 ChatGPT、豆包、Coze、Trae，以及其他不同类型的 AI 产品。

我开始尝试 Agent、工作流、AI Coding，也开始关心一个工具究竟能够完成多少真实工作。

第二阶段的关键词：交付。

03

第三阶段：我开始意识到，单个工具没有那么重要

到了 2026 年年中，我又经历了一次明显的变化。

一方面，一些原来长期使用的工具发生了产品调整，我发现原本非常顺手的工作方式，可能因为一次版本变化就被打断。

另一方面，豆包工作、WorkBuddy 等面向工作场景的 AI 产品开始出现。

这个阶段让我第一次真正意识到：

一个 AI 工具本身再强，如果进不了我的工作生态，它对我的实际价值依然有限。

我长期使用飞书。

很多知识、项目资料、问题记录，以及工作关系都沉淀在飞书里。

所以当我重新选择 AI 工具时，我开始越来越重视一件以前没有那么在意的事情：

集成能力。

比如现在，豆包工作依然是我愿意长期保留的工具之一。

并不是因为我认为它在所有能力上都是最强的，而是因为它可以比较自然地进入我已经长期使用的飞书生态。

一个 AI 如果能直接进入这些已有的上下文，它创造的价值，往往比单独多一个很厉害的功能更大。

第三阶段的关键词：生态与连接。

04

第四阶段：从 AI 工具使用者，到 AI 原生开发者

而最近这段时间，我觉得自己的角色又发生了一次更根本的变化。

以前，我主要是在不同 AI 产品之间做选择。

现在，我越来越多地开始直接使用：

• 大模型 API

• Coding Agent

• CLI

• GitHub

• MCP

• Open API

• 数据库与其他开发工具

去搭建自己真正需要的东西。

也正是在这个过程中，我突然发现：

很多以前觉得非常重要的 AI 产品，正在慢慢变成可以替换的组件。

以前我会问：Trae 好不好用？

现在我更关心：

我需要一个什么样的 Coding Agent？

它是否支持我需要的模型？

上下文管理怎么样？

能不能执行代码、进入 Git 工作流？

成本和稳定性怎么样？

如果一个工具可以接入 DeepSeek，并且已经能够满足我的开发需求，那么我就没有必要仅仅因为习惯继续为另一个 Coding 产品付费。

工具开始从“身份”变成“组件”。

05

ChatGPT 依然是我的智囊团，但不需要所有事情都由它来做

有意思的是，走了一大圈以后，ChatGPT 在我的工作方式里依然非常重要。

只是它的位置变了。

产品方向、方案设计、一个突然冒出来的想法，甚至一些还没有完全想明白的东西，我依然愿意先拿来和它讨论。

它依然是我的“智囊团”。

但真正进入开发以后，我已经不再要求所有事情必须由同一个 AI 完成。

我希望由自己决定产品按照什么节奏推进，而不是让某一个工具的套餐、额度或者产品形态决定我的节奏。

06

我终于不再执着于寻找“最好用的 AI”

以前看到一个新的 AI 工具，我经常会产生一种冲动：

这个是不是比我现在用的更好？

要不要换？

是不是别人已经在使用更先进的东西了？

但现在，这种焦虑越来越少了。

因为我开始发现，根本不存在一个脱离场景的“最好用”。

如果我要思考一个模糊的问题，ChatGPT 对我很好用。

如果我要调用自己长期沉淀在飞书里的信息，那么能够进入飞书生态的工具对我更重要。

如果我要大量开发代码，我会选择更适合 Coding、成本也更可控的模型和工具。

如果我要开发自己的产品，那 API、数据库、权限、系统集成和工程能力，就会比某一个聊天产品的界面重要得多。

我现在更习惯按照这个顺序思考：

① 我要解决的究竟是什么问题？

② 这里到底需要什么能力？

③ 哪个模型、工具或 API 最适合承担这部分能力？

顺序反过来了。

07

从 Tool-centric，到 Capability-centric

如果一定要给这一年多的变化做一个总结，我觉得可以用两个词：

Tool-centric → Capability-centric

以前：工具中心

我有什么 AI 工具，就看看它能帮我做什么。

现在：能力中心

我需要完成这件事情，因此我要组合哪些能力？

于是，一个完整任务可能变成：

ChatGPT 帮我讨论产品逻辑；

另一个模型负责 Coding；

GitHub 管理代码和版本；

飞书承载业务数据和协作；

Open API 负责不同系统之间的连接；

数据库保存长期数据；

Agent 负责执行某些规则明确的工作。

AI 不再只是一个聊天窗口。

它开始变成整个系统中的一个能力节点。

而我自己的角色，也从 AI 工具使用者，逐渐变成 AI 系统的设计者和开发者。

✦

写在最后

这一年多，我其实并没有停止寻找新的 AI 工具。

相反，我可能比以前接触得更多。

只是现在，我很少再期待：

“下一个工具会不会解决我所有的问题？”

因为真正能够长期留下来的，可能从来都不是某一个具体工具。

工具会改版，模型会升级，价格会变化。今天最热门的产品，半年之后也可能已经不是主角。

但有些东西会留下来：

所以现在，如果有人再问我：

“哪个 AI 工具最好用？”

我可能不会急着给出一个工具名字。

我会先问：

你到底想拿它做什么？

用 AI 一年多以后，我越来越相信：真正值得长期积累的，从来不是对某个工具的熟练度，而是把不同 AI 能力组合起来、解决真实问题的能力。
